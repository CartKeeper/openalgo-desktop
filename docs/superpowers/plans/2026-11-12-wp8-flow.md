# WP8 — Flow (Visual Workflow Builder) Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upstream OpenAlgo Desktop's Flow — a drag-and-drop canvas of 61 node types that trade, with schedule, price-alert, order-update and webhook triggers — runs in this app against US brokers, in Eastern time, with workflows importable from and exportable to OpenAlgo web unchanged.

**Architecture:** Carry, don't rewrite. The Flow module is taken from `upstream/master` (`marketcalls/openalgo-desktop`, v1.0.7; the `upstream` remote is already configured) with `git checkout upstream/master -- <paths>`, then adapted at a fixed list of seams: this app's `AppState`, no event bus (an order-update poller feeds a broadcast channel), no tunnel (the webhook config's `ngrok_url`), no Agent (its indicator library is carried as `indicators_lib`), no keystore (always unlocked; `SecurityManager` encrypts webhook secrets), Eastern market time, US exchanges and `CNC`. Nodes reach the broker through the app's own `/api/v1` axum handlers via an in-process `tower::ServiceExt::oneshot` call, which keeps the exact JSON shapes the nodes were written against. `/flow/api/*` becomes 22 Tauri commands returning `FlowReply { status, body }`; the public webhook stays an HTTP route. Four sequential phases, each merged on its own.

**Size, stated plainly:** upstream's Flow is about 1.4 MB of Rust (a quarter of it tests), 1.4 MB of TypeScript (more than half tests), 787 golden fixtures (2.7 MB), plus a 252 KB indicator library and one git dependency. Phase A alone is larger than WP1–WP7 together.

**Tech Stack:** Rust (tokio, axum 0.7 + `tower` `util` for oneshot, chrono-tz `America::New_York`, `rust_decimal`, `oa_core` git crate), `@xyflow/react@12.12.1`, `@uiw/react-codemirror`, `@codemirror/lang-json`, Tailwind 4 tokens (this app and upstream both use `--color-*` tokens).

**Spec:** `docs/superpowers/specs/2026-11-12-ports-program-design.md` (WP8 requirements; thresholds rows "Flow market time" through "Flow default product"; open item 4).

## Global Constraints

- Branches `wp8a-flow-core`, `wp8b-flow-ui`, `wp8c-flow-triggers`, `wp8d-flow-parity`, each cut from the integration branch after the previous phase merged. Files: everything under `src-tauri/src/flow/`, `src-tauri/src/indicators_lib/`, `src-tauri/src/messaging/`, `src-tauri/src/clock.rs`, `src-tauri/src/events.rs`, `src-tauri/src/security/secret.rs`, `src-tauri/src/state.rs`, `src-tauri/src/webhook/server.rs` + `handlers.rs` (internal-trust check only), `src-tauri/src/commands/flow.rs`, `src-tauri/src/commands/telegram.rs`, the frontend Flow tree, `src/App.tsx`, `src/config/navigation.ts`, `src/index.css`, `src/pages/telegram/*`, plus WP8 anchors.
- Market time is `America/New_York` everywhere Flow reads a clock; market hours come from `market_status_service::get_clock`/`get_calendar`, never a constant. Upstream's `ist_*` names are renamed, not aliased.
- Secrets (webhook secrets, Telegram token) are encrypted at rest with `SecurityManager::encrypt`, never logged, never in fixtures; the request log must redact `/flow/webhook/<token>`.
- No node ever places an order outside the app's existing order path (`/api/v1/*` handlers → `OrderService`/sandbox), so analyzer mode, rate limits and Gate B apply unchanged.
- The validator accepts upstream's Indian exchanges **and** this app's US exchanges `NYSE, NASDAQ, AMEX, ARCA, BATS, OTC, US, CRYPTO`; default product on a US exchange is `CNC`.
- Unsupported in this app and answered as a clear node error, not a crash: `whatsappAlert`, `strategyPnl`, margin lookups that need an Indian broker.
- Gates per phase: `cd src-tauri && cargo test --lib` (goldens included), `npx vitest run`, `npm run build`, `npm run lint`.

## Review Focus

1. A workflow saved in IST on OpenAlgo web and imported here: schedule times are reinterpreted as Eastern and the import reply says so. (Phase A Task A3 test "imported daily 09:15 becomes 09:15 ET and the reply carries the note".)
2. Daylight-saving transitions: a daily 09:35 schedule fires at 13:35Z before 2026-11-01 and 14:35Z after; a `timeWindow` spanning 02:00 on 2026-03-08 does not double-fire. (A3 tests.)
3. The app exits while a run is between two order legs: the run is recorded `interrupted` at start-up, never silently resumed. (A6 test using `executions::close_interrupted`.)
4. A webhook replay (same body twice within a second) and wrong-secret storms: the second run is `already_running` or queued per upstream's claim; wrong secrets lock the webhook after the guard's limit. (C3 tests.)
5. The broker disconnects mid-run: broker-backed nodes fail with the handler's message, the run ends `failed`, the trigger stays registered. (A8 test with the sandbox off and no broker session.)
