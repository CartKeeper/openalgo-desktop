# WP6 — TA-Lib Indicators Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server-side indicator service computes 200+ TA-Lib indicators and 61 candlestick patterns, exposed through a catalog the Fundamentals → Analysis tab can pick from.

**Architecture:** The official TA-Lib Rust crate (`ta-lib` 0.8, BSD-3, pure Rust, generated from the C reference) replaces the `ta` crate. `indicators_service.rs` keeps its `IndicatorResult` shape and the `compute_indicators` command, adds a catalog-driven dispatcher, and re-aligns TA-Lib's `OutRange` output to the input timestamps. A new `indicator_catalog` command feeds the dropdown.

**Tech Stack:** `ta-lib = "0.8"` (MSRV 1.88), Rust, React Select with groups.

**Spec:** `docs/superpowers/specs/2026-11-12-ports-program-design.md` (WP6 requirements).

## Global Constraints

- Branch `wp6-talib-indicators`; files below plus WP6 anchors.
- TA-Lib's numbers are authoritative. Where the old `ta`-crate seeding differs (EMA seeds with the SMA of the first period in TA-Lib; RSI uses Wilder smoothing with TA-Lib's unstable period), existing tests' expected values are updated and the commit body says why.
- `ta = "0.5"` is removed from `Cargo.toml` once `grep -rn "use ta::" src-tauri/src` is empty.
- Request parameter names stay backward compatible: `period`, `fast`, `slow`, `signal`, `std_dev`; new ones follow TA-Lib's names in snake_case.
- Output alignment: a value for input index `i` sits at `values[i]`; indices before the lookback are `None`.

## Review Focus

1. Series shorter than the lookback: TA-Lib returns success with zero values; the service returns all-`None`, never an error or a panic. (Task 3 test.)
2. NaN or infinite inputs (bad bars): rejected with `AppError::Validation` naming the bar index. (Task 3 test.)
3. Parameters out of TA-Lib's range (e.g. period 1 for RSI): mapped to `AppError::Validation` with the allowed range from the catalog, not a `RetCode` debug string. (Task 3 test.)
4. Multi-output indicators (MACD, BBANDS, STOCH, AROON): every output is returned with its TA-Lib name and the same alignment. (Task 3 test.)
5. Candlestick patterns on fewer than their lookback bars (some need 12+): all-`None`. (Task 3 test.)

### Task 2: Catalog

**Files:**
- Create: `src-tauri/src/services/indicator_catalog.rs`
- Modify: `src-tauri/src/services/mod.rs` (WP6 anchor)

**Interfaces:**
- Produces:
  ```rust
  #[derive(Clone, Serialize)] pub struct ParamSpec { pub name: &'static str, pub default: f64, pub min: f64, pub max: f64, pub kind: &'static str /* "int"|"float"|"matype" */ }
  #[derive(Clone, Serialize)] pub struct IndicatorSpec { pub name: &'static str /* TA-Lib name, e.g. "ADX" */, pub label: &'static str, pub group: &'static str /* Overlap | Momentum | Volatility | Volume | Cycle | Statistics | Patterns */, pub inputs: &'static [&'static str] /* subset of open, high, low, close, volume */, pub params: &'static [ParamSpec], pub outputs: &'static [&'static str] }
  pub fn catalog() -> &'static [IndicatorSpec]
  pub fn find(name: &str) -> Option<&'static IndicatorSpec>   // case-insensitive
  ```

VWAP stays an app-computed entry (`group: "Volume"`, not TA-Lib).
